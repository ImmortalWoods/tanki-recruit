# tanki-recruit

Поиск игроков и автоматическая отправка приглашений в клан через «Военкомат» Lesta. Для работы аккаунту нужны права на приглашение игроков. Поддерживаются Linux и Windows 10/11.

Скрипт использует отдельный профиль Chromium: пароль вводится вручную в окне браузера. Данные аккаунта, включая cookie, хранятся только на компьютере: в Linux — `~/.local/share/tanki-recruit/`, в Windows — `%LOCALAPPDATA%\tanki-recruit\`. Не передавайте эту папку другим людям.

## Установка

Нужны Python 3.10+, модуль `venv`, доступ к сети и графическая сессия для входа. В Windows установите Python с python.org, включив «Add Python to PATH».

**Linux:**

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python login.py main
```

**Windows (PowerShell):**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe login.py main
```

Войдите в Lesta в открывшемся окне и нажмите Enter в терминале. Проверка входа подтверждает открытие страницы набора, но не права на отправку приглашений. Если Chromium сообщает об отсутствующих системных библиотеках, установите зависимости Playwright для вашей системы.

## Поиск и приглашения

```bash
.venv/bin/python candidates.py                 # только поиск
.venv/bin/python candidates.py --send --limit 5  # отправить до пяти приглашений
```

В Windows вместо `.venv/bin/python` используйте `.\.venv\Scripts\python.exe`.

По умолчанию при отправке действует предел 10 приглашений за запуск. Поиск запрашивает список по страницам отдельно для каждого уровня подбора и за два периода. На сайте нет надёжного общего числа результатов, поэтому скрипт проверяет фиксированный диапазон: `MAX_PAGES = 100` страниц по `PAGE_SIZE = 100` позиций для каждой из шести комбинаций уровня и периода (до 600 запросов за запуск). Пустые страницы не останавливают поиск; за пределами диапазона могут оставаться кандидаты. Значение `MAX_PAGES` можно изменить в `candidates.py`. Игроки с неполной статистикой пропускаются, их количество выводится отдельно. При повторе страниц, пустом общем результате или отсутствии полной статистики у всех игроков работа останавливается с ошибкой.

Критерии меняются в начале `candidates.py`:

```python
MIN_BATTLES = 5000       # минимум боёв за всё время
MIN_WIN_PERCENT = 53     # минимум процентов побед за всё время
MIN_BATTLES_PER_DAY = 5  # минимум боёв в день в среднем за последние 28 дней
```

`PERIOD_DAYS = 28` соответствует фиксированному периоду сайта и его не следует менять без изменения запроса.

Перед отправкой подходящему игроку скрипт проверяет его приглашения в списке клана. Если действующее приглашение уже есть, игрок пропускается. Если прежнее приглашение истекло или отклонено, игрок может получить новое при очередном подходящем прогоне. Отдельной рассылки прежним кандидатам нет.

Попытки приглашения записываются в файл `invitations.sqlite3` в каталоге данных. Отправка считается подтверждённой после корректного ответа и появления нового приглашения в списке клана. Если результат неоднозначен (например, соединение прервалось), работа останавливается, чтобы избежать повторной отправки. При явном отказе сайта попытку можно повторить после устранения причины. Если сессия истекла, повторите вход. Не удаляйте базу без необходимости: она защищает от повторных отправок.

Посмотреть незавершённые попытки (в Windows вместо `.venv/bin/python` используйте `.venv\Scripts\python.exe`):

```sh
.venv/bin/python candidates.py --pending
```

Проверьте каждого игрока в разделе приглашений клана на сайте, затем укажите его ID из вывода команды:

```sh
.venv/bin/python candidates.py --resolve-pending ID --resolution sent   # приглашение найдено
.venv/bin/python candidates.py --resolve-pending ID --resolution retry  # приглашения нет, разрешить повтор
```

Повтор разрешайте только после проверки: при неопределённом результате первое приглашение могло быть отправлено. После разрешения всех незавершённых попыток можно снова запустить поиск или дождаться автоматического запуска.

## Автозапуск в Linux

После ручной проверки установите таймер systemd:

```bash
sh install-systemd.sh
systemctl --user list-timers tanki-recruit.timer
journalctl --user -u tanki-recruit.service -n 100
```

Таймер запускает отправку ежедневно около 09:00 по местному времени, до 10 приглашений за запуск. При ошибке служба пытается показать уведомление через `notify-send`. Для ручного запуска используйте `systemctl --user start tanki-recruit.service`; для отключения — `systemctl --user disable --now tanki-recruit.timer`. После перемещения проекта повторно запустите установщик.

Автоматизация зависит от сайта Lesta: при изменении его API или отсутствии доступа к аккаунту может понадобиться обновление скрипта или повторный вход.

## Автозапуск в Windows

После входа и ручной проверки поиска выполните в PowerShell из папки проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\install.ps1
```

Задача `TankiRecruit` запускается ежедневно в 09:00, когда пользователь вошёл в Windows. Пропущенный запуск выполняется после входа. Действует ограничение 10 приглашений за запуск. Журнал находится в `%LOCALAPPDATA%\tanki-recruit\recruit.log`; уведомлений Windows об ошибке пока нет. Проверить результат и время следующего запуска можно в планировщике заданий. Удаление автозапуска:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\uninstall.ps1
```

Если проект перемещён, повторите установку задачи. Для нестандартного каталога данных переменную `TANKI_RECRUIT_DATA` нужно задать постоянно в окружении пользователя до установки и входа в Windows.
